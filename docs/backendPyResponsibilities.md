# AtlasWorks Backend Python 模块职责说明

本文档用于说明 `atlasWorks/backend` 下每个 Python 文件的职责、当前定位和边界，便于后续继续产品化、拆分和交接。

## 总体结构

- `app.py`
  Flask 启动入口。
  负责创建应用、初始化 CORS、挂载静态页面目录、执行启动阶段 bootstrap，并调用 `routeRegistry.py` 注册全部路由。

- `routeRegistry.py`
  路由注册中心。
  负责把 URL 路径和具体业务函数绑定起来，避免 `app.py` 继续膨胀成路由堆场。

- `taskState.py`
  任务状态规范层。
  负责创建和归一化 `taskStatus` 结构，降低不同业务模块之间的任务字段差异。

## 基础设施模块

- `config.py`
  全局配置与进程内状态中心。
  负责环境变量读取、目录配置、数据库配置、任务状态表、任务进程表、停止标记表和任务锁。

- `db.py`
  PostgreSQL 持久化适配层。
  负责数据库连接、任务快照、任务事件、产物记录、发布记录等数据库读写。

- `utils.py`
  通用工具函数库。
  负责日志输出、数值归一化、命令执行、内存单位换算、路径校验、任务进程停止等跨模块共享能力。

## 数据源与预检查

- `dataSourceOps.py`
  数据源域逻辑。
  负责浏览数据源目录、读取 GeoTIFF 基本信息、波段信息、自动推荐切片参数、预估最佳缩放级别、解析输入文件列表。

- `preflight.py`
  构建前预检查模块。
  负责在实际切片或地形构建前校验输入文件、投影、波段、输出覆盖风险、工具链是否可用以及粗略资源估算。

- `fileSplitOps.py`
  大文件拆分模块。
  负责把超大栅格拆成多个较小 TIF，既提供 API 接口，也提供内部调用的拆分函数。
  当前已修复为可在 Windows 上正常工作的顶层 worker 结构，不再依赖嵌套进程函数。

## 切片与地形

- `indexedTilesOps.py`
  索引切片主业务模块。
  负责 TIF 搜索、瓦片网格索引、空间范围裁剪、并行切片、波段预处理、空瓦片扫描删除、索引文件生成和高性能/超高性能切片路径。

- `terrainOps.py`
  地形切片主业务模块。
  负责基于 CTB 的 terrain 生成、解压、`layer.json` 更新、任务状态推进和最终产物落库。

- `tileAdminOps.py`
  瓦片运维与管理模块。
  负责瓦片目录结构转换、缓存目录扫描、TIFF 优化、按缩放级别执行 `gdal2tiles`。

## 任务、系统、工作区

- `taskCenter.py`
  任务中心模块。
  负责任务列表、任务详情、事件流、清理任务、停止任务、删除任务等任务管理动作。

- `systemOps.py`
  系统运维模块。
  负责健康检查、系统信息、API 路由说明、容器环境更新时间/配置/缓存等系统级接口。

- `workspaceOps.py`
  工作空间与结果目录管理模块。
  负责结果目录浏览、文件详情、创建/删除/重命名文件夹、删除文件、统计工作区大小等能力。

## 产物与发布

- `artifacts.py`
  构建产物收尾模块。
  负责在任务完成后整理 `manifest.json`、构建参数摘要、产物记录和任务事件。

- `catalog.py`
  产物与发布台账模块。
  负责列出产物、查看产物详情、读取 manifest、创建发布记录、查询发布信息。

## 当前状态判断

- 当前后端已经从“单体 service.py”切换为“按领域分模块”结构。
- `app.py` 和原 `service.py` 的职责已经基本拆散完。
- 现在的核心主线已经比较清晰：
  数据源 -> 预检查 -> 索引切片/地形切片 -> 产物落库 -> 发布管理 -> 工作区管理。

## 目前仍未完全完成的点

- 缺少测试层
  目前主要靠 `py_compile` 和 `docker compose config` 做静态校验，缺少接口级和任务级自动化测试。

- 路由文档仍偏代码侧
  虽然已有 `/api/routes` 和本说明文档，但还没有一份面向产品/前端/外部调用方的标准 API 文档。

- 任务模型还不够统一
  不同模块写入 `taskStatus` 的字段命名和状态文案仍有细微差异，后续最好统一成标准结构。

- 模块内部还有可继续清理的重复工具
  例如部分模块内仍有本地 helper，可继续向 `utils.py` 收敛。

- 分幅、缓存、TIFF 优化等能力虽然已经模块化
  但还没有做完整的端到端回归验证，尤其是 Windows、本地 Python、Docker 三种环境的一致性验证。

- 前端/嵌入式页面已落地第一版
  当前已经有内嵌控制台页面，但仍属于“运维控制台 + JSON 表单”阶段，还没收敛成真正的产品化向导界面。

- 发布能力仍是基础版
  当前是 manifest + publication 记录模式，还没有真正的多目标发布流程，比如 3D Tiles、GeoJSON、OBJ、GLB、外部服务挂载等产品化发布通道。
